## Кінематографічна сцена

- Ланцюжок рендеру: `RenderPass → UnrealBloomPass → Vignette/Grain → OutputPass`. ACES Filmic, exposure `1.15`, PCF Soft Shadows. Bloom: strength `0.85`, radius `0.55`, threshold `0.25`; grain `0.025`. Half-float буфери й MSAA зберігають HDR та згладжування. Світлові матеріали випромінюють HDR, а відбите світло має м’яку компресію яскравості, щоб не засвічувати папір, шкіру й пелюстки при низькому порозі Bloom.
- Великий шейдерний SkyDome із нічним смарагдовим градієнтом та повільною авророю; шість далеких скелястих силуетів на Z −15…−34. Вода на Y −0.65 малює плавні кільця та процедурне бурштинове відбиття світла. Це шейдерне відбиття, не додатковий дзеркальний рендер усієї сцени. Три радіальні шари туману й окремі передні боке-частинки вздовж траєкторії камери створюють глибину.
- Острів має три шумово деформовані тераси, окрему щільну поверхню з кам’яно-моховими вертексними кольорами, скульптурні валуни, три світлові кристали з м’якими об’ємними променями. 4500 інстансованих трисегментних травинок і 96 дрібних папоротей рухаються у вершинному шейдері. Теплий відтінок кінчиків залежить від відстані до лотоса.
- Лотос: 36 замкнутих параметричних пелюсток у чотирьох ярусах, заокруглені загнуті кінчики, градієнт ivory → ruby. `MeshPhysicalMaterial`: transmission `0.35`, thickness `0.6`, roughness `0.45`. Дихання пелюсток, світлова сфера з двома ореолами, внутрішній PointLight та вертикальний промінь.
- Замість стола — кам’яний вівтар із заглибленими світловими кільцями й трьома гнучкими каліграфічними аркушами. Перемикання вкладок обертає їх на третину орбіти; швидкі повторні натискання зберігають кінцеві позиції. Лінії та краї вигинаються разом із папером, вилітають п’ять золотих іскор.
- Замість скрині — шестисегментний керамічний кокон кінцуґі. На етапі приватності сегменти змикаються, захищене ядро зникає за оболонкою, золоті шви посилюють світіння. При поверненні кокон відкривається.
- Світлова верба: п’ять переплетених трубчастих стовбурів, розлога крона з 360 інстансованих листочків, 42 світлові нитки, три ребристі `LatheGeometry`-ліхтарики. Верхівки ниток закріплені, рухаються лише нижні ділянки. FAQ і Raycaster керують відповідними ліхтариками, підвісні шнури точно слідують за їхньою позою.
- Наш GLB-аватар завантажується за замовчуванням. SHA256 збігається з моделлю основного сайту. Усі 16 кісток зберігають вихідні масштаби та скручування; персонаж сидить на округлій моховій подушці, дихає, реагує на курсор, одноразово вітається й жестикулює під час відповіді. Теплий SpotLight відділяє силует від неба. Процедурний персонаж доступний лише при помилці завантаження GLB; breakdance-кліп не запускається.
- 180 світлячків мають індивідуальні розміри, фази та кольори amber → mint gold. Рух реагує на швидкість скролу. Ядро завжди сферичне, цикл дихання — 4 секунди вдих / 6 секунд видих. Reduced motion вимикає вітер, паралакс, плавання острова й привітання.

## Збережена поведінка

HTML/CSS, тексти, п’ять етапів, вікна видимості панелей, Lenis/ScrollTrigger, клавіатурна навігація, нативний help-dialog, звук та локальна розмова збережені. Фінальна камера `[0, 1.35, 1.85]`, ціль `[0, 0.55, -0.8]`. Для нових вертикальних артефактів уточнено висоту погляду й поле зору проміжних кадрів; камери не заходять у їхні захисні об’єми. Перед фіналом верба й бічні станції плавно зникають.

Чат залишається локальною демоверсією. Повідомлення потрапляють у DOM через `textContent`, довжина обмежена 500 символами, тези зберігаються лише за вибором і зникають після оновлення. Web Speech API може надсилати аудіо сервісу браузера — інтерфейс попереджає про це. Відмова в доступі до мікрофона обробляється. При втраті WebGL зберігаються HTML, навігація й чат, доступний перезапуск 3D.

## Продуктивність і перевірки

Статична геометрія об’єднана за матеріалами, рослини інстансовані; вітер, туман і нитки рухаються на GPU. DPR обмежений 1.5 на телефоні / 1.75 на комп’ютері. Порцелянове заломлення використовує буфер половинної роздільності для матового матеріалу. Карта м’яких тіней оновлюється кожен третій кадр, освітлення й анімації — кожен кадр. Кількість джерел світла стабільна при переходах. Геометрія, текстури, матеріали, скелети, post-processing passes і render targets звільняються при демонтажі.

Після запуску dev server:

```powershell
npm test
npm run test:cinematic
```

За одночасно запущених dev і production preview:

```powershell
npm run test:production
```

Запускайте тести послідовно для коректного заміру GPU. Chromium: `npx playwright install chromium`. На Windows використовується апаратний D3D11.

- Основний тест: 22 сценарії, зокрема кількості об’єктів і параметри рендеру, GLB/кістки, переходи вперед/назад, аркуші, кокон, FAQ, Raycaster, чат/XSS, тези, контрольований голосовий ввід, axe WCAG A/AA, 390×844 / 320×568 / 1000×600, повторні взаємодії та відновлення WebGL.
- Production-тест: реальні кнопки під CSP, завантаження нашого GLB, робочий чат, одноразове привітання, сферичне дихання ядра, відсутність JS/мережевих/CSP-помилок.
- Замір кінематографічної сцени: усі п’ять зупинок, 1440×900, DPR 1.25, звичайна анімація. На RTX 3060 Laptop отримано медіану близько 82 FPS; p95 часу кадру близько 18.3 ms. Це вимір на цьому ПК, не гарантія для будь-якого обладнання. Мінімальний виміряний запас до захисних об’ємів артефактів на маршруті — близько 0.59 одиниці.

Звіти та знімки: `.checks/verification.json`, `.checks/production-verification.json`, `.checks/cinematic-performance.json`, `.checks/FINAL.json`. Початкові й наступні ТЗ збережені у `SPECIFICATION.md`, `SPECIFICATION-UI-FIX.md`, `SPECIFICATION-CINEMATIC.md`.

Порядок HDR-постпроцесингу звірений з [офіційною документацією Three.js](https://threejs.org/manual/pages/post-processing.html); параметри порцеляни — з [MeshPhysicalMaterial](https://threejs.org/docs/pages/MeshPhysicalMaterial.html).
