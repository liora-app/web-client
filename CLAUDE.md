# liora-app / web-client — правила для AI-асистентів

Web frontend: лендінг Liora. Частина організації `liora-app` (ADR-003).

- **Спільні правила, рішення й процес — у репо `devops`**: `CLAUDE.md`, `CONTRIBUTING.md`,
  `docs/adr/`. Прочитай їх перед пропозиціями; ADR пишемо там.
- Стек — ADR-006: Vite + TypeScript + three.js, без UI-фреймворку. Нову мову, фреймворк чи
  залежність — лише з ADR у `devops/docs/adr`.
- Текст — тільки в DOM, `<canvas>` декоративний (`aria-hidden`). Сторінка мусить бути повною без WebGL.
  Жодних форм, аналітики, cookies і сторонніх запитів (шрифти — локально).
- Подача — як в ADR-006: глави з великою моно-типографікою й рядками, **без сіток карток, glass-панелей
  і градієнтного тексту**. За WebGL-канвасом лежить лише заголовок hero; увесь текст для читання — над ним.
  Приглушення — кольором `--color-text-dim`, ніколи `opacity` (контраст ≥ 4.5:1).
- Шейдери на прозорому канвасі віддають premultiplied-колір (rgb ≤ alpha).
- Тексти про продукт: саморефлексія, **не** терапія і не медична допомога; прямо кажемо, що це AI;
  не обіцяємо того, чого немає в договорі з AI-провайдером; кризові контакти — 112, 103 і
  howareu.com/hot-lines (7333 на паузі, не друкуємо).
- Перед PR: `npm run build` і `npm run test:e2e` локально (у конфігу не більше 3 воркерів — не піднімай:
  кожен воркер — браузер з WebGL, WebKit під Windows рендерить його програмно).
- Гілки `<type>/<issue>-<slug>`, Conventional Commits англійською, squash-merge, без комітів у `main`.
- CI-логіку тут не міняй — вона в `devops/.github/workflows/reusable-*.yml`.
- Хвилини Actions обмежені (Free): не додавай jobs і тригерів без потреби.
- Жодних реальних діалогів, імен чи контактів користувачів — тільки синтетичні дані. Секрети — тільки в `.env`.
